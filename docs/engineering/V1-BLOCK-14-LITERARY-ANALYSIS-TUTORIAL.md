# WriteStorm V1：文学作品拆解、技法提炼与长篇生产指导教程

## 文档定位

本文是一份面向 WriteStorm V1 的指导教程。它把学院叙事学、文体学、相关经验研究、作者与编辑实践，以及 WriteStorm 已裁决的产品边界组合成可执行的文学拆解方法。

它的目的不是：

- 宣称文学理论天然只有七个模块；
- 把某一套网文、轻小说或戏剧公式当成所有小说的质量标准；
- 用一份教程替代权威决策记录、Schema、Prompt 或运行设计；
- 要求模型在一次长篇分析中逐项执行所有研究规则。

它的目的在于帮助分析者依次回答：

1. 原文实际写了什么？
2. 故事世界中发生了什么？
3. 文本怎样选择、排列和表达这些内容？
4. 人物、关系、世界条件、语言模式与意义结构怎样形成？
5. 哪些解释有证据，哪些仍是推断、竞争解释或未知？
6. 哪些做法可以进一步提炼为有条件的写作技法？

### 1.1 七个核心分析模块

当前核心分析层由七个模块组成：

1. **故事情节**：故事事件、因果与情节线；
2. **叙述调度**：叙述结构与信息调度；
3. **人物塑造**；
4. **关系动力**；
5. **世界设定**：世界设定、环境与规则；
6. **语言文体**：语言与文体；
7. **主题意蕴**：主题、象征模式与意义结构。

卷、章、Story segment 和 TextRange 属于结构与范围层。专题视角、技法提炼、约束治理、AI 约束摘要及续写上下文属于下游层。它们都不是第八个核心分析模块。

七模块是 WriteStorm 为“单写者、多读者”、独立审查和局部修订而采取的产品边界，不是学院文学研究唯一正确的分类法。

## 二、资料分级：不同来源能证明什么

### 2.1 学院叙事学、文体学与文学解释理论

这类资料主要提供概念边界和分析方法，例如：

- Story 与 Discourse 的区分；
- 事件时间与文本呈现时间的区分；
- 叙述者、聚焦者、人物与真实作者的区分；
- 文体形式及其功能的分析方法；
- 主题、母题、象征和意识形态解释的证据边界。

它们可以支持“应当区分什么”，但不能直接证明 WriteStorm 必须采用某一种数据库结构或七模块划分。

### 2.2 实证研究与计算叙事研究

这类资料可以提供：

- 人物目标怎样参与事件理解；
- 人物互动、关系弧和社会网络为何具有分析价值；
- 事件层级、事件关系与文本分段为何不能只靠简单标签；
- 长篇摘要和事件关系评估为什么需要多种检查协议。

它们通常研究特定语料和任务，不能自动推广为所有小说的文学规律，也不能替代产品裁决。

### 2.3 作者、编辑和平台经验

这类资料回答实际创作中的问题，例如：

- 何时让读者理解主角与故事承诺；
- 怎样使用人物关系、对话、阶段目标、悬念和回收；
- 作者怎样用大纲、场景表或人物关系继续长篇创作。

这些经验有直接参考价值，但必须保留适用条件。不同作者甚至会采用相反的方法：有人先写总体梗概和场景，有人从人物、世界和关系自然发展故事。它们不能被升级为 Base 的普遍强制规则。

### 2.4 软件与知识工程

领域建模、CQRS 和依赖治理主要帮助解决：

- 同一事实由谁拥有；
- 规范事实与查询视图怎样分离；
- 怎样避免多模块双写；
- 怎样进行局部修订、版本追踪和选择性 stale。

这些工程思想能验证系统设计是否一致，却不能证明文学分析对象本身应当怎样划分。

可参考：

- [Microsoft：领域驱动设计中的领域模型](https://learn.microsoft.com/en-us/dotnet/architecture/microservices/microservice-ddd-cqrs-patterns/microservice-domain-model)
- [Microsoft：CQRS Pattern](https://learn.microsoft.com/en-us/azure/architecture/patterns/cqrs)

### 2.5 WriteStorm 产品裁决

Story segment、资产准入、Scope 规则、模块所有权和完成门禁属于产品裁决。它们将前述知识转化为可审查系统，但不冒充学院理论。

## 三、所有分析共同遵守的推理纪律

### 3.1 从证据到写作方法的完整链条

分析应按以下层级前进：

```text
原文范围与版本
→ 可观察事实
→ 领域解释
→ 跨模块综合
→ 功能或效果假说
→ 可复用写作方法
→ 用户采纳后的写作约束
```

例如：

```text
连续出现三个短句
→ 当前文本形成短促句法模式
→ 与追逐事件、有限聚焦和信息缺口共同出现
→ 可能强化紧迫和受限感
→ 在需要压缩感知与行动间隔时可尝试短句加速
```

不能从“三个短句”直接跳到“读者一定紧张”，也不能跳到“所有战斗都应使用短句”。

### 3.2 五种容易混淆的认识状态

分析时至少要区分：

1. 文本实际呈现了什么；
2. 人物知道、相信或误解了什么；
3. 叙述者声称了什么；
4. 基于文本结构，模型化读者可能推断什么；
5. 真实读者实际理解或感受了什么。

第五项需要真实接受资料。没有读者数据时，可以提出“可能形成悬念的机制”，不能确认“读者必然紧张”。

### 3.3 事实、解释和审查状态不能混成一个标签

同一结论应分别记录：

- 它是文本明确、叙述者归因、人物主观归因，还是分析推断；
- 它当前是候选、受支持、证据不足、竞争解释、未决还是被拒绝；
- 它依赖哪些原文锚点和其他领域结论。

内部即使允许 `confirmed + analysis_inference` 之类的双轴状态，面向用户也应表达为“受支持解释”或“已接受推断”，不能伪装成文本明说的事实。

### 3.4 单写者、多读者

每类权威事实只由一个领域拥有，其他模块通过稳定引用使用。

例如：

- 人物目标由人物塑造拥有；
- 某次行动和直接结果由故事情节拥有；
- 关系信任状态由关系动力拥有；
- 能力规则与资源约束由世界设定拥有；
- 何时向读者揭示规则由叙述调度拥有；
- 规则的象征意义由主题意蕴解释。

页面可以组合展示这些内容，但不能在多个模块分别保存一份可修改的相同事实。

### 3.5 不确定性是合法结果

以下结果都可以是诚实分析的一部分：

- 未发现；
- 不适用；
- 证据不足；
- 存在竞争解释；
- 当前 unresolved；
- 原文有意保持未知。

“完成分析”不等于强迫每个关注面产生正向结论。

### 3.6 分析顺序是语义层级，不是机械重读次数

完整拆解可以按以下语义次序组织：

1. 冻结书、卷、章、Story segment 和原文范围；
2. 重建事件、身份、人物状态、关系状态和世界条件；
3. 分析叙述者、聚焦、呈现顺序、信息隐藏和揭示；
4. 分析词汇、句法、修辞、对话与思想呈现；
5. 综合主题问题、反复意义模式、价值冲突和竞争解释；
6. 从合格来源提炼技法及其适用条件。

这六层不是要求把一本长篇机械读取六遍。一次共享扫描可以发现多个领域候选；不同模块可以复用同一证据锚点；上层解释只在实际依赖的来源合格后确认。物理调用次数和批次属于生产配置。

## 四、结构层：把长篇冻结为可分析范围

### 4.1 结构层拥有什么

结构层只负责：

- 书；
- 卷；
- 章；
- Story segment；
- 标题、顺序、包含关系和原文范围；
- 活动 `structureEdition`。

结构层不拥有：

- 铺垫、高潮和转折；
- 人物目标和关系状态；
- 聚焦、悬念和信息揭示；
- 主题、象征和技法解释。

其他模块可以解释结构形式，但不能把文学解释反写成结构事实。

### 4.2 Story segment 的当前产品定义

Story segment 是用户冻结在活动结构版本中的卷内连续分析分区。它把需要结合理解的一段正文组织为稳定 Scope，供七模块共同定位证据、运行分析、审查和展示。

当前产品强制要求：

- 每部长篇至少具有一个活动 Story segment；
- 每卷正文由 Story segment 无缝、无重叠、完整覆盖；
- Story segment 必须连续；
- 可以在章内开始或结束，也可以跨章；
- 不得跨卷。

“不跨卷”是 WriteStorm 的导航、冻结和治理约束，不是文学理论声称故事发展不能跨卷。跨卷连续发展由 Plotline、EventRelation 和上层综合表达。

### 4.3 Story segment 怎样划分

Story segment 不要求完整的“起承转合”，也不要求独立高潮、闭合情节线或完整人物弧。

普通边界需要比较两侧：

- 前侧是否有一个局部发展或情境中心告一段落、失败、暂停或转向；
- 后侧是否由另一个持续发展或情境中心接管；
- 切分后，两侧是否仍能形成可结合理解的范围。

时间跳跃、地点变化、视角切换、章节标题、人物组合变化等只是辅助线索，不能单独机械确认段界。多个辅助线索如果共同支持持续中心的变化，可以构成主要证据。

人物沉思、环境展开、书信、梦境、过渡和语言实验仍必须归入最合适的 Story segment。没有独立情节脉络不等于 Story segment 无效。

### 4.4 Story segment 不是唯一客观真相

小说分段研究说明场景和段界识别需要标注规范，也存在判断差异。[Detecting Scenes in Fiction](https://aclanthology.org/2021.eacl-main.276/) 可以支持“分段不是天然唯一”的谨慎立场，但它研究的 scene 不等同于 WriteStorm 的 Story segment。

因此：

- AI 可以提出候选分区和局部替代边界；
- 用户冻结当前活动结构；
- 冻结的是运行范围，不是唯一文学真相；
- 范围变化首先影响覆盖、投影和范围综合；
- 原文锚点仍有效的规范事实不因重新分段而自动失效。

## 五、学院分析基础

### 5.1 Story 与 Discourse：先分清“发生什么”和“怎样讲”

叙事学常区分：

- **Story**：故事世界中按逻辑和时间发生的事件；
- **Discourse**：文本怎样选择、排列、隐藏、重复和呈现这些事件。

参考：[Purdue：Story 与 Discourse](https://cla.purdue.edu/academic/english/theory/narratology/terms/story.html)、[Cambridge：Events and Plot](https://www.cambridge.org/core/books/abs/psychonarratology/events-and-plot/C2A9547C8B58828C62F6E6C07AD97928)。

#### 教材式重建步骤

第一步，暂时脱离文本顺序，列出故事世界中的事件：

```text
事件 A：国王死亡
事件 B：王子离开首都
事件 C：王子得知死讯
事件 D：王子返回
```

第二步，记录文本实际呈现顺序：

```text
文本先写 D
→ 回忆 B
→ 揭示 A
→ 最后补充 C
```

第三步，比较两种顺序：

- 哪些事件被提前或推迟？
- 哪些事实被省略？
- 哪些事件被重复讲述？
- 同一事件是否由不同人物重述？
- 呈现顺序怎样改变暂时理解？

这一步可以识别倒叙、预叙、延迟揭示、多视角重述和叙述性诡计，也是故事情节与叙述调度必须分开的主要依据。

### 5.2 叙述时间：顺序、时长与频率

Genette 传统通常从三方面分析叙述时间：

- **Order**：事件发生顺序与文本呈现顺序；
- **Duration**：故事经历时间与文本篇幅的关系；
- **Frequency**：事情发生次数与被讲述次数。

参考：[图宾根大学：Narrative Time](https://uni-tuebingen.de/en/233933)。

| 文本现象 | 故事时间 | 文本篇幅 | 常用说明 | 可分析的问题 |
| --- | --- | --- | --- | --- |
| 一场五秒战斗写三页 | 很短 | 很长 | 减速 | 是否放大选择、感知或关键结果 |
| 三个月旅途写一段 | 很长 | 很短 | 概述 | 哪些重复过程被压缩 |
| 房间描写时行动停止 | 近乎停顿 | 持续展开 | 停顿 | 环境、聚焦或象征承担什么作用 |
| “十年后”一句带过 | 十年 | 一句 | 省略 | 断裂隐藏了什么变化 |
| 同一事故被三人回忆 | 一次发生 | 三次呈现 | 重复叙述 | 认识和可靠性怎样变化 |

“节奏快慢”不能只看事件多少。它还可能来自叙述篇幅、句法、信息密度、停顿、省略和聚焦方式，需要由叙述调度与语言文体共同解释。

### 5.3 叙述者、聚焦者与人物不能混同

- 叙述者回答：谁在讲？
- 聚焦回答：信息通过谁的感知、知识或立场被过滤？
- 人物回答：故事世界中谁在行动、知道、相信或误解？
- 真实作者不等同于虚构叙述者。

参考：[Cambridge：Focalization](https://www.cambridge.org/core/books/abs/cambridge-companion-to-narrative/focalization/4292F5EB30ACFBB54BD1F8D4A920BED5)。

对一段文本可以追问：

1. 谁发出叙述声音？
2. 谁在感知当前场景？
3. 谁能够知道这条信息？
4. 这句话是事实陈述、人物思想、自由间接话语还是双重声音？
5. 叙述者知道的是否超过人物？
6. 信息是否被隐藏、误解或歪曲？
7. 聚焦是否切换，切换是否清楚？

第三人称不自动等于全知；没有引号的评价也不自动属于作者。

### 5.4 文本信息与读者效果不能短路

信息延迟、风险未决和认识差异可能形成悬念、好奇或惊讶机制，但形式不能直接证明所有真实读者都产生同一反应。

参考：[Suspense, Curiosity and Surprise](https://www.sciencedirect.com/science/article/pii/S0304422X99000212)、[Frontiers：Suspense and prediction](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2018.01392/full)。

因此可以说：

- “这里延迟给出关键因果信息”；
- “人物与模型化读者存在知识差”；
- “该安排可能形成悬念机制”。

没有接受数据时，不应说：

- “读者一定被骗”；
- “所有读者都会紧张”；
- “这一段必然爽”。

## 六、七模块的教材化分析方法

### 6.1 故事情节：故事世界怎样发生变化

故事情节的根本任务是重建并解释故事世界中的变化过程：

- 发生了什么？
- 局面改变了什么？
- 变化怎样连接？
- 它们形成了怎样的持续发展？

它不等于剧情简介，也不负责评价情节是否精彩、爽、紧凑或符合某种公式。

基础分析可以采用：

```text
人物目标或外部条件
→ 选择与行动
→ 阻碍、条件或其他事件
→ 直接结果
→ 领域状态变化
→ 后续选择空间改变
```

人物目标对事件因果理解具有重要作用，但目标仍由人物塑造拥有。参考：[人物目标与阅读理解研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC4266429/)、[Open Book Publishers：Motivation and Plot](https://www.openbookpublishers.com/books/10.11647/obp.0283/chapters/10.11647/obp.0283.09)。

故事情节的当前深层方法见第七章。

### 6.2 叙述调度：文本怎样组织信息

叙述调度分析：

- 叙述者与叙述层级；
- 聚焦及其变化；
- 故事事件的呈现顺序；
- 叙述时长和频率；
- 场景、概述、停顿与省略；
- 明示、隐藏、延迟、重复、修正和揭示；
- 文本单元怎样开合、衔接和制造认识变化。

它拥有“文本何时、以何种来源呈现某事”，不拥有“某事是否在故事世界中真实发生”的第二份事实。

对参考写作的帮助包括：

- 设计有限信息；
- 管理人物知识与读者可知信息；
- 分析倒叙、误导、悬念和揭示；
- 区分公平隐藏与无证据欺骗；
- 研究多视角怎样重释同一事件。

叙述调度尚未完成与故事情节同等级的产品深度冻结。本节是教程方法，不是最终 Schema 规格。

### 6.3 人物塑造：人物在各阶段是谁、为何行动

人物分析至少关注：

- 稳定身份；
- 阶段目标；
- 动机与需要；
- 知识、信念和误解；
- 价值判断与内部矛盾；
- 能力、限制和掌握状态；
- 关键选择；
- 稀疏的人物阶段；
- 人物弧线综合。

#### 证据来源要分开

| 证据来源 | 能直接支持什么 | 主要风险 |
| --- | --- | --- |
| 叙述者陈述 | 叙述者作出该陈述 | 叙述者可能不可靠 |
| 人物自述 | 人物如此描述自己 | 自欺、表演或操纵 |
| 他人评价 | 他人持有该看法 | 偏见、信息不足 |
| 可观察行为 | 人物确实做了什么 | 单次行为未必是稳定特质 |
| 有代价的选择 | 特定处境下的目标或价值排序 | 仍需结合压力与可选项 |
| 分析推断 | 证据共同支持的解释 | 不能冒充文本明说 |

“人物说自己勇敢”不自动证明勇敢；有代价的选择通常更有解释力，但也不能脱离处境和可行替代选项。

人物阶段不是每章一份心理快照。只有目标、身份、知识、信念、能力或关键解释发生实质变化时，才需要建立新阶段。人物弧线是阶段状态、关键选择和变化方向的综合，不是第二套事实。

### 6.4 关系动力：多个主体怎样持续相互作用

关系分析关注：

- 正式或公开关系；
- A 对 B 与 B 对 A 的不同认知；
- 信任、权力、亲密、依赖、义务和冲突；
- 关系阶段和触发变化；
- 双人、多人、家庭、群体、组织和联盟关系；
- 一方选择怎样改变另一方的行动空间。

关系必须允许：

- 有方向；
- 不对称；
- 公开关系与双方认识不同；
- 随事件与阶段变化；
- 单向互动和双向互动承担不同作用。

共同出场不自动构成深层关系。可以保存轻量关系事实，只有持续影响选择、情节、信任、权力或人物变化时，才进入深层分析。

[角色互动研究](https://aclanthology.org/2024.nlp4dh-1.45/)和[计算叙事学中的关系弧研究目录](https://www.cambridge.org/core/journals/computational-humanities-research/themed-issues/computational-narratology)支持人物互动与动态关系轨迹具有独立分析价值；它们不证明“关系动力”必然是学界唯一七分法中的独立模块。

关系动力尚未完成产品深度冻结。本节只提供分析方向。

### 6.5 世界设定：环境、制度、资源和规则怎样约束行动

广义 storyworld 可以包含人物、事件、环境和状态。WriteStorm 为避免世界模块吞并人物与情节，将其产品责任收窄为：

- 地理、空间与环境；
- 物质条件和资源；
- 社会制度与组织规则；
- 文化规范；
- 技术与能力体系；
- 限制、代价、例外和适用条件。

参考：[Open Book Publishers：Setting](https://www.openbookpublishers.com/books/10.11647/obp.0187/chapters/10.11647/obp.0187.03)。该资料说明 setting 可以具有地形、氛围、功能、心理和象征维度；WriteStorm 仍将环境事实与意义解释分开。

规则分析可以依次检查：

1. 文本宣称规则是什么；
2. 谁知道、相信或误解该规则；
3. 规则在哪些事件中实际生效；
4. 是否存在例外；
5. 例外是否预先建立；
6. 规则带来什么限制或代价；
7. 它怎样改变人物可选路径。

所有权示例：

- 能力的一般定义、限制和代价：世界设定；
- 人物是否持有、掌握或误解能力：人物塑造；
- 实际使用能力造成的行动与结果：故事情节；
- 何时向读者披露能力规则：叙述调度；
- 能力的象征意义：主题意蕴。

世界设定尚未完成产品深度冻结。本节只提供分析方法。

### 6.6 语言文体：当前文本版本具体怎样表达

文体分析不能只给作品贴“优美、简洁、有网感”的标签。它应落实到可观察形式及其分布。

参考：[Cambridge：Language and Style](https://www.cambridge.org/highereducation/books/stylistics/8D6D7ABF3463EB974DCD3420D8124116/language-and-style/083690CD80C8670C87394E4E0FC37DAA)、[Cambridge：Theories and Methods in Stylistic Analysis](https://www.cambridge.org/core/books/abs/stylistics/theories-and-methods-in-stylistic-analysis/8C7021E0501DA985B853BBC27FCB3B4A)。

#### 分析层级

1. **词汇与语域**
   - 口语或书面；
   - 具体或抽象；
   - 方言、术语、网络语；
   - 感官和评价词群。
2. **句法与标点**
   - 长短句；
   - 主从结构；
   - 省略、断裂、重复；
   - 主动与被动；
   - 标点和停顿。
3. **修辞与前景化**
   - 隐喻、转喻、对比；
   - 排比、反复、陌生化；
   - 意象怎样由语言实现。
4. **言语与思想呈现**
   - 直接引语；
   - 间接引语；
   - 自由间接话语；
   - 内心独白与思想报告。
5. **模式与变化**
   - 是否反复出现；
   - 在什么场景和人物上出现；
   - 与其他范围相比怎样变化；
   - 是否与叙述、人物和事件共同作用。

单个短句不足以确认一种文风。稳定作者风格通常需要跨作品和类型基线；单本书只能可靠分析当前作品、当前版本的文本风格。

翻译作品必须记录语言、原文或译文、译者和版本。只有译本时，可以分析译本文体，不能把译者的所有词汇和句法选择归于原作者。

关于叙事、语言与翻译的基础教材可参见 [Open Book Publishers：Prose Fiction](https://www.openbookpublishers.com/books/10.11647/obp.0187)。

语言文体尚未完成产品深度冻结。

### 6.7 主题意蕴：作品怎样组织可竞争的意义解释

主题意蕴分析关注：

- 作品反复提出的主题问题；
- 不同人物、事件和形式给出的竞争答案；
- 反复意象与意义模式；
- 象征关系；
- 价值冲突；
- 叙事立场中的支持、质疑、并置和矛盾；
- 形式与意义的联系；
- 替代解释和反证。

#### 主题不是普通话题

“爱情”“战争”“成长”只是话题。主题分析应继续追问：

- 作品反复提出什么问题？
- 存在哪些竞争答案？
- 哪些事件、人物、叙述和语言模式支持这些答案？
- 结局解决、回避还是保持矛盾？

#### 母题或反复意义模式不是高频词

准入至少需要：

- 多个可定位出现；
- 语境、功能或形式发生变化；
- 能够说明这些出现为何属于同一模式；
- 保留替代解释和反证。

单次但重要的对象只能先作为象征候选，不能伪装成反复模式。参考：[Cambridge：Motifs](https://www.cambridge.org/core/books/cambridge-companion-to-narrative-theory/motifs/4909F15EAD7A2A9CDB8194313EC10B19)。

#### 解释必须可验证，而不是寻找唯一真意

解释需要说明证据覆盖、内在一致性、替代解释和可能推翻它的材料。参考：[Cambridge：Validation of Interpretative Conclusions](https://www.cambridge.org/core/books/abs/structure-of-literary-understanding/validation-of-interpretative-conclusions/3AE3AF5E6A83A14BCDE442FFD2223665)。

人物的一句价值判断首先属于人物，不直接成为叙事立场。只有情节后果、叙述距离、人物对照、反复模式、结局处理和语言讽刺等共同形成支持、质疑或并置时，才适合讨论叙事立场。

意识形态分析也不能把作品中的单个人物观点直接等同于作品立场。它需要检查哪些价值和社会秩序被自然化、质疑、奖惩、沉默或保留矛盾，并区分文本内部解释与分析者带入的外部框架。参考：[Cambridge：Ideology](https://www.cambridge.org/core/books/cambridge-companion-to-narrative/ideology/38F671676EAAC233E72CA9D8FF86BFD7)。

作者意图、历史语境、类型史、互文关系和真实读者接受需要外部来源。作品内部的意义解释不能用模型记忆替代这些来源。

主题意蕴尚未完成产品深度冻结。

## 七、故事情节的当前深层方法

本章只提供 D131 后领域语义的准确教学摘要。资产字段、ID、审查协议和完整不变量仍以[故事情节权威记录](./V1-BLOCK-14-STORY-PLOT-CROSS-EXAMINATION-RECORD.md)为准。

### 7.1 四类规范资产与两类非规范结果

故事情节当前具有四类规范领域资产：

1. **StoryEvent**：准入结构化故事事件；
2. **EventRelation**：可独立审查的事件关系命题；
3. **Plotline**：持续发展对象及其发展记录；
4. **PlotlineRelationClaim**：情节线之间的身份谱系或有来源的发展互动。

另外还有：

- **Scope 投影**：根据规范资产确定性查询出的非权威视图，不调用 AI，不成为第二事实源；
- **StandardStoryRecap**：有来源、可审查、可 stale 的派生回顾资产，不拥有底层事实。

这六种内容不是平级事实，也不共享同一生命周期。

### 7.2 StoryEvent：什么值得结构化保存

文学作品当然包含大量动作和发生过程。WriteStorm 的 StoryEvent 是产品“准入结构化故事事件”，不是宣布只有被建档的动作才算文学事件。

某个发生过程通常在承担至少一种独立情节作用时才值得稳定保存，例如：

- 造成或保护了人物、关系或世界状态；
- 改变人物目标的推进或实现状态；
- 成为因果、条件或阻碍中的独立节点；
- 对 Plotline 产生可独立引用的发展作用；
- 形成持续约束、后果或待审查的未决发生命题。

普通吃饭、开门和走路通常无需分别建档；如果它们共同形成一个不可再无损压缩的结果，可以构成复合事件；其中某一步产生独立后果时，才需要自己的事件身份。

### 7.3 事件内部的语义组按需出现

一个事件以发生命题为核心，并可按需表达：

- 参与者及其事件内角色；
- 故事时间；
- 空间定位；
- 直接结果；
- 人物能动性；
- 主体对本次行动结果的意图或预判。

这些都不是全量必填表。自然事件可以没有行动主体；地点和时间不明时，不必批量制造空的 `unknown` 命题；普通动作也不应为了填满字段而升级为正式事件。

能动性和预期结果只在影响关键选择、因果理解、成败比较或下游复用时深入检查。它们引用人物目标、知识、信念、关系压力和世界约束，不复制这些状态。

### 7.4 直接结果的单写者边界

直接结果只表达同一事件语义过程的即时落点。“即时”是语义上的直接，不要求钟表时间非常短。

例如：

- “尝试开门，但门没有打开”可以是同一事件的直接结果；
- “按下开关，灯熄灭”可以是同一事件的直接结果；
- 后续另一人物决定掩护并被捕，已经形成新的行动者、选择和因果阶段，应成为独立事件。

一旦结果具备独立事件资格、独立因果节点资格，或已经由人物、关系、世界的状态转变命题拥有，StoryEvent 内部就不能再保存同义的第二份结果。

### 7.5 复合事件、父子事件与事件组

事件认知和事件抽取研究支持粗细粒度事件及 part-whole 关系：

- [Episodes, Events, and Models](https://www.frontiersin.org/journals/human-neuroscience/articles/10.3389/fnhum.2015.00590/full)
- [HiEve](https://aclanthology.org/L14-1020/)
- [MAVEN-ERE](https://aclanthology.org/2022.emnlp-main.60/)

但这不意味着所有宏观名称都要成为正式父事件。

- 只有父过程本身具有可独立取证的宏观发生、过程状态、整体结果或因果作用时，父事件才能与子事件共存；
- 纯命名、导航或摘要整体只能是只读 EventGroup；
- `part_of` 必须无环；
- 多父归属只有在语义不矛盾且查询能够去重时才合法；
- 父子事件不能复制同一行动、结果和审查事实。

### 7.6 传闻、梦境与未决事件

“人物说 P 发生了”首先证明人物作出该陈述，或文本呈现了该内容，不自动证明 P 在故事世界中真实发生。

- 传闻、梦境、预言、假设和反事实默认属于叙述呈现；
- 收到、相信或传播传闻本身可以构成信息事件；
- 只有“P 是否真实发生”需要跨证词合并、持续影响行动或长期审查时，才建立未决 StoryEvent；
- 未决事件不能作为“已经实际发生”的确认因果前提；
- 后来真实发生的事件不能反写成早期梦境当时已经发生。

分析应尽量把争议落在最小命题上。若“B 死亡”已确认但死因未知，应保留一个死亡事件，并把“被推下楼”与“意外跌落”表达为竞争的行动或因果命题，而不是复制两份死亡事实。

### 7.7 故事时间采用约束和偏序

小说往往没有统一日期，也可能包含并行、重叠、循环和多个时间框架。故事时间不应被强迫成一条完整线性时间轴。

事件可以表达：

- 明确时间点或区间；
- 模糊时期；
- 持续时间；
- 重复或习惯性过程；
- 与其他事件同时或重叠；
- 顺序竞争或未知。

事件自身的时间定位属于 StoryEvent；事件之间的先后、同时和重叠属于 EventRelation；历法、纪年和时间框架定义属于世界设定；倒叙、预叙和文本呈现位置属于叙述调度。

系统只应投影证据支持的偏序。回忆出现在第五章，不代表被回忆事件发生在第五章。

### 7.8 EventRelation 的关系族

EventRelation 不是“两个节点之间随便贴一个标签”，而是一条有端点、方向、来源组合、关系类型、认识身份和证据的可审查关系命题。

当前关系族摘要如下：

| 关系族 | 典型端点 | 回答的问题 |
| --- | --- | --- |
| temporal | StoryEvent → StoryEvent | 先于、同时、重叠、时间包含或顺序未知 |
| motive | 合格人物目标/动机命题 → 行动事件 | 人物为何采取该行动 |
| causal_mechanism | 事件、直接结果或合格领域状态命题 → 事件、直接结果或合格领域状态转变命题 | 来源怎样造成、形成条件或构成阻碍 |
| potential_consequence | 有证据的事件、规则、状态或条件 → 关系内部的条件性结果命题 | 某条件下可能发生什么 |
| outcome_comparison | 预期结果命题 → 直接结果、后续事件或合格领域状态转变 | 意图/预测与实际结果怎样对应 |
| structural_containment | 子 StoryEvent → 父 StoryEvent | 事件之间的 `part_of` |
| noncausal_association | 合格事件或结果命题之间 | 有独立证据和价值的“有关但非因果”联系 |

`unresolved` 是认识状态，不是新的关系族。

仅仅时间相邻仍优先由 `temporal` 表达；暂时找不到因果机制也不能自动命名为巧合或 `noncausal_association`。

因果机制基础子类限制为：

- cause；
- condition；
- obstacle。

必要条件、使能、促成等更细判断，只有确实改变文学解释、审查或下游用途时才进一步表达，不能把所有关系做成过密分类。

领域状态转变可以成为因果和结果比较端点，但状态内容仍由人物、关系或世界模块单写。潜在后果如果没有其他既有领域所有者，其结果内容保留在拥有它的 EventRelation 内部，不凭空创建第五类资产。

人物相信 A 导致 B，只证明人物的因果归因；分析推断的因果可以经过审查成为受支持解释，但必须保留推断身份、机制、竞争解释和推翻条件。时间相邻不能自动确认因果。

### 7.9 Plotline：持续发展对象怎样组织事件

Plotline 不是人物、地点、类型或主题标签。它必须围绕一个可持续追踪的发展对象，并实际组织跨事件发展，例如：

- 某项任务能否完成；
- 某个威胁怎样发展；
- 某个秘密如何暴露；
- 某种关系、组织或局面将走向何处；
- 某种状态变化轨迹怎样持续形成。

它可以由文本明确的强前向承诺开启，也可以由多个事件和状态变化经过分析归纳形成。普通愿望、共同地点、同一人物频繁出现或 ContentFocus 命中都不足以自动建立 Plotline。

同一 Plotline 跨 Story segment、卷和全书保持一个身份。某卷没有推进记录不表示它暂停，跨卷延续也不建立新线。

### 7.10 发展作用与生命周期必须分开

Plotline 的发展记录只表达五类作用：

- `develops`：发生了实质发展，不等于更接近成功；
- `maintains`：有行动或条件维持现状，阻止本会发生的变化；
- `obstructs`：增加困难、代价、延迟或限制；
- `turns`：仍追踪同一对象，但策略、认识、条件或可行路径持续改变；
- `decides`：核心结果已被实质确定或结果空间不可逆收窄。

以下变化只由 LifecycleRecord 表达：

- `opens`；
- `pauses`；
- `resumes`；
- `reopens`；
- `closes`。

当前生命周期投影为：

- `open`；
- `paused`；
- `closed`；
- `unresolved`。

`unresolved` 是投影结果，不是一个生命周期动作。`decides` 可以早于 `closes`；一条线也可以逐渐失去追踪必要而关闭，并不存在单一“决定事件”。

某个 Scope 没有相关事件、人物没出场或叙述切线，都不能自动推导暂停。暂停必须有发展实际停止而追踪义务仍存在的证据。

### 7.11 主导性是 Scope 判断

“主导”不是 Plotline 的永久属性。应在具体 Scope 内判断：

- 它是否组织进入局面到离开局面的关键变化；
- 当前最小充分故事链是否必须包含它；
- 重要事件、状态变化或其他线是否受其约束；
- 删除它后，是否无法解释该范围为何发展到当前结果。

篇幅、出场次数、事件数量和主角参与只是证据维度，任何单项都不能自动决定主导性。一个 Scope 可以有一条、多条或无法确认唯一主导线。

并行、支持、交叉和汇合描述线之间的关系，不应与主导性压成永久单选标签。

### 7.12 StandardStoryRecap：有选择的回顾，不是摘要拼接

每个活动 Story segment、每卷和全书都必须处理“故事回顾关注面”，但不保证每个范围都创建 Recap 资产。

只有存在可以忠实压缩的变化链时，才创建 StandardStoryRecap。否则记录：

- 已检查但未发现足够故事过程；
- 当前范围不适用；
- 证据不足；
- 存在关键 unresolved；
- 只能作为相邻或上级脉络的一部分理解。

这些都是完成关注面的合法处置，不应生成空壳回顾。

Recap 的通用骨架是：

1. 进入局面；
2. 最小充分变化链；
3. 离开局面；
4. 延续与未决。

“最小充分变化链”是一种压缩判断：只保留解释范围关键变化、人物必要选择、因果桥梁和未决承接所需的内容。它不是第五类规范资产。

Recap 必须：

- 从规范事件、关系、Plotline 及合格跨领域引用重新选择；
- 不按章或子 Scope 平均抽样；
- 不拼接下级摘要；
- 保留关键竞争解释和未知；
- 不引入底层不存在的新事实。

章默认使用确定性 Scope 投影和关联 Story segment 回顾。查看章节不能临时触发 AI；独立章回顾只有明确产品用途时才作为目的版本生成。

## 八、跨模块所有权与下游综合

### 8.1 常见交界面的唯一所有者

| 现象 | 权威所有者 | 其他模块怎样使用 |
| --- | --- | --- |
| 人物长期/阶段目标 | 人物塑造 | 情节引用它解释选择与行动 |
| 一次行动及直接结果 | 故事情节 | 人物引用它解释塑造或变化 |
| 信任、权力、依赖状态 | 关系动力 | 情节引用其对事件和 Plotline 的作用 |
| 能力定义、资源、制度规则 | 世界设定 | 情节引用其作为条件或阻碍 |
| 事件何时被讲述 | 叙述调度 | 情节只保存故事世界发生时间 |
| 人物声音的词汇和句法模式 | 语言文体 | 人物页可组合展示其塑造意义 |
| 反复意象的意义模式 | 主题意蕴 | 文体拥有具体语言实现 |
| 真实读者反应 | 接受资料 | 七模块只能提出有条件效果假说 |

跨模块引用必须最终回到原文证据，不能形成循环论证：

```text
因为人物有该目标，所以事件是目标驱动；
因为发生了该事件，所以人物一定有该目标。
```

如果人物目标只能由该事件推断，必须保留分析推断身份和替代解释。

### 8.2 Block 15 专题视角

专题视角重新组合七模块已经形成的合格事实和解释，例如：

- 情绪与节奏；
- 主角魅力；
- 关系张力；
- 能力成长；
- 世界可信度；
- 连载吸引力。

它不是把来源材料机械拼在一起，也不能在缺乏基础信息时凭空生成新事实。若专题需要某类可独立审查的基础信息，首先应回看七模块是否有权威所有者和合格证据。

### 8.3 Block 16 技法提炼

来源模块回答“这本书具体做了什么”；技法层回答“这些做法怎样共同运作、在什么条件下可能有效、能否去专名复用”。

技法不是预设名称匹配。应主动寻找：

- 重复与变化；
- 前后对照；
- 延迟、遮蔽和揭示；
- 知识不对称；
- 压缩与扩张；
- 长距离呼应与回收；
- 角色印象重构；
- 跨卷和跨 Story segment 接力。

一项技法应尽量形成：

```text
文本操作
→ 作用对象
→ 运作机制
→ 功能或效果假说
→ 替代解释与反证
→ 适用及失效条件
→ 去除原作专名后的复用表达
```

### 8.4 约束治理

七模块只产出可用于形成写作约束的来源结论，不直接拥有正式 AIConstraint。

约束可能来自：

- 已确认的原作分析；
- 经审查的技法；
- 用户明确选择的方法论；
- MainType Base 和 ContentFocus；
- 产品安全、原创与引用规则。

这些来源不能互相冒充。约束治理域负责适用目标、强度、优先级、冲突、例外和版本；AI 约束摘要只是只读组合。

## 九、作者与编辑实践：可借鉴，但不升格为普遍规律

### 9.1 日本 Web 小说与轻小说实践

[Kakuyomu 关于第一话和故事目标的访谈](https://kakuyomu.jp/info/entry/kkymcn11_interview_1)说明，有作者会尽早让读者理解主角和目标，以便读者判断作品承诺；它不能推出所有作品必须在第一章明确终极目标。

[Kakuyomu 关于场景与情节设计的访谈](https://kakuyomu.jp/info/entry/kakuyomukoshien2022_interview03)展示了先准备总体梗概、再拆场景的创作路径，同时明确不同作者方法不同。

[Kakuyomu 对晓佳奈的访谈](https://kakuyomu.jp/info/entry/kakuyomukoshien2023_akatsukikana)则展示了另一种路径：不依赖固定 Plot，而让世界、人物和关系推动故事。

这些材料共同支持的不是某一个公式，而是：

- 创作需要可恢复的故事承诺、人物关系和阶段发展；
- 作者可以借助不同粒度的回顾或计划继续写作；
- 产品应支持多种方法，不能让一种作者习惯成为 Base 硬门禁。

### 9.2 中国网络小说与连载实践

中国网络小说研究和作者编辑经验经常重视：

- 人物愿望与持续阻碍；
- 阶段目标和长篇动力；
- 冲突、悬念、回收和章节衔接；
- 连载中的信息重复与读者恢复成本。

可参考：[中国网络小说结构研究](https://jnxb.jnu.edu.cn/skb/CN/Y2019/V41/I5/84)。

“黄金三章”“每章钩子”“固定高潮密度”等只适用于特定平台、类型和追读目标。它们可成为 Overlay、用户方法或技法候选，不得判断所有文学作品是否合格。

### 9.3 创作者怎样回顾前文

创作者继续长篇时通常不是重新阅读全部原文，也不是只读一篇静态摘要。实用回顾往往组合：

- 当前阶段进入局面；
- 正在发展的主要问题；
- 关键人物目标、知识和关系状态；
- 最近改变局面的选择与结果；
- 尚未回收的承诺、风险和信息；
- 下一步仍可行动的路径。

WriteStorm 的 StandardStoryRecap 可以承担稳定回顾的一部分，但“续写上下文简报”是动态下游用途，还需要组合人物、关系、世界、叙述和用户当前写作目标。它不是故事情节模块的第五类事实，也不要求每次查阅都重新调用 AI。

## 十、长篇生产：当前候选，不是冻结运行方案

### 10.1 七模块不等于把书机械读七遍

模块划分是事实所有权和审查边界，不规定物理调用次数。实际运行可以：

- 共享扫描原文锚点；
- 在一次调用中提出多个领域候选；
- 将跨域候选路由给唯一所有者；
- 复用已确认身份和证据；
- 只在冲突、上下文不足、版本变化或消歧需要时回读相关文本。

候选没有下游权威。只有领域所有者可以合并、拆分、拒绝或提升正式资产。

### 10.2 当前六问运行骨架候选

为避免把 Q1—Q47 变成每次运行的超长清单，当前生产候选用六个问题组织故事情节发现：

1. 当前范围发生了什么可追踪变化？
2. 谁选择、行动或遭遇了什么，直接结果是什么？
3. 这些变化怎样连接？
4. 它们影响了什么持续发展？
5. 是否存在矛盾证词、未决发生、不可靠来源或只有声称的内容？
6. 支持当前判断的最小充分证据是什么？

这六问：

- 不是六种资产；
- 不是用户界面的固定六栏；
- 不是已经冻结的 Prompt；
- 不能替代条件触发和领域校验。

### 10.3 条件触发候选

只有文本与用途实际需要时，才深入检查：

- 人物能动性；
- 意图结果与预测结果；
- 风险或潜在后果；
- 精细故事时间；
- 父子事件；
- Plotline 间关系；
- 精细 EventRelation；
- 未决事件命题。

ID、去重、循环、端点、Schema 版本、事务和审查权限应主要由程序验证，不应让模型靠自然语言反复自检。

### 10.4 为什么生产配置仍然 OPEN

长上下文模型会受信息位置影响，[Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/)说明仅仅扩大上下文窗口不保证稳定使用全部材料。

[CELLO：Can Large Language Models Understand Real-World Complex Instructions?](https://ojs.aaai.org/index.php/AAAI/article/view/29777)研究复杂指令遵循，可用于支持“规则过载会造成约束遗漏”的生产风险。CELLO 不是长篇叙事事件理解基准，不能拿来证明故事事件抽取质量。

[EventRelBench](https://aclanthology.org/2025.findings-emnlp.482/)说明事件关系理解本身仍是需要专门评估的任务，但它也不能预判 WriteStorm 尚未实现的 Prompt 表现。

因此 Block 17 仍需比较至少四种实验臂：

1. 仅六问；
2. 六问加经过验证的条件触发；
3. 六问加全部文学深层卡；
4. 原始 Q1—Q47 过载压力组。

当前推荐候选是第二组，但在真实长篇对照前不能冻结。

### 10.5 生产质量不能靠门禁数量保证

门禁能阻止已知错误，却不能自动保证：

- 模型注意力没有被规则分散；
- 长距离事件没有漏掉；
- 多模块候选没有身份漂移；
- 摘要选择真正忠实；
- 文学解释对专家有用。

每增加一个模块或门禁，都要回答：

- 它拦截什么具体错误？
- 该错误是否高频或高影响？
- 能否由程序验证而不是消耗模型注意力？
- 是否重复了其他规则？
- 触发成本是否低于纠错收益？

Q30 保持 `PROVISIONAL`，正是因为生产质量必须通过实验而不是文档完整度确认。

## 十一、六类技法怎样按教程拆解

### 11.1 用细节增强现实感

先分别检查：

- 细节是否具体；
- 是否受环境、制度和资源约束；
- 是否符合人物经验和生活习惯；
- 是否参与后续行动或因果；
- 是否只是无关名词堆积。

再形成有条件解释：

> 具体、受约束且能参与行动或后续因果的日常细节，可能成为现实锚点。

“现实感”是功能假说；真实读者是否觉得可信仍需要接受资料。

### 11.2 标签式工具人如何获得厚度

比较：

- 早期是否只有单一情节功能；
- 是否长期只以他人视角呈现；
- 后期是否出现独立目标；
- 是否作出有代价的选择；
- 新信息是否重新解释过去行为；
- 少量篇幅为何足以改变人物模型。

可提炼为：

> 先建立稳定功能预期，再用独立欲望、矛盾和有代价选择重构角色。

### 11.3 叙述性诡计

分别重建：

1. 故事世界中实际发生的事件；
2. 文本怎样呈现；
3. 谁知道什么；
4. 代词、聚焦或语言怎样制造歧义；
5. 模型化读者何时可以形成哪些推断；
6. 后文怎样修正首次理解。

不能因为模型第一次猜错，就确认文本实现了公平叙诡；也不能因为模型提前猜到，就断言所有读者都能猜到。

### 11.4 跨卷与跨 Story segment 衔接

检查：

- 前一范围留下什么未决发展；
- 哪些事件结果继续生效；
- 人物、关系和世界状态怎样承接；
- 是否通过人物、物件、问题、视角或意象接力；
- 新范围是连续推进、跳跃承接还是故意断裂。

结构只提供边界。衔接技法来自情节、叙述、人物、关系、世界、语言和意义的综合。

### 11.5 怎样分析“水字数”

先中性描述篇幅增加，再分别测量：

- 事件与状态变化；
- 信息增量；
- 人物塑造；
- 关系变化；
- 环境与氛围；
- 语言形式；
- 主题或意象功能；
- 连载回顾与读者恢复用途。

排除这些合理功能后，才能提出“疑似无功能扩写”“重复解释”或“相对当前目标可压缩”。不能用事件密度低直接判定水字数。

### 11.6 伏笔与回收

至少检查：

- 前文线索可以定位；
- 首次出现具有局部合理功能；
- 后文是否实际依赖该线索；
- 回收是否参与因果或改变理解；
- 是否违反既有事实；
- 是否存在更简单的替代解释。

“作者故意埋伏笔”需要意图资料；仅凭当前文本更稳妥的表述是“前后形成了可验证的提示—重释或提示—兑现关系”。

## 十二、验证与长篇质量评估

### 12.1 不能只用一种评估

长篇摘要和叙事分析中的错误可能包括：

- 事实错误；
- 人物或事件身份混淆；
- 跨章节因果断裂；
- 漏掉关键局部信息；
- 摘要整体流畅但局部不忠实；
- 局部句子都对，但整本书脉络失衡；
- 对主观、视角性问题强造唯一答案。

单次人工判断和单一自动指标都可能漏掉这些问题。

相关研究：

- [SNaC：叙事摘要错误分类](https://aclanthology.org/2022.emnlp-main.29/)
- [STORYSUMM：长篇故事摘要评估](https://aclanthology.org/2024.emnlp-main.557/)
- [LongEval：长文本摘要评估](https://aclanthology.org/2023.eacl-main.121/)
- [NarraBench：叙事理解评估覆盖](https://aclanthology.org/2026.eacl-long.176/)

NarraBench 尤其提醒：许多叙事任务带有主观性、视角性或多种合理解释，不能都压成单一标准答案。

### 12.2 评估至少覆盖四个层面

1. **局部证据**
   - 命题能否定位原文；
   - 来源身份是否正确；
   - 否定、条件和指代是否保留。
2. **规范资产**
   - 身份是否稳定；
   - 是否重复；
   - 所有权是否正确；
   - EventRelation 端点与类型是否有效。
3. **范围与长距离一致性**
   - 跨 Story segment 和卷的 Plotline 是否连续；
   - 结构变化是否只影响真实依赖；
   - 追加连载是否保留旧版有效事实。
4. **派生回顾与解释**
   - 是否忠实；
   - 是否连贯；
   - 是否遗漏关键变化；
   - 是否保留重要未知和竞争解释；
   - 是否为流畅而补造因果。

### 12.3 生产对照指标

真实长篇实验应同时比较：

- 关键事件、关系和 Plotline 遗漏率；
- 普通动作误升级率；
- 重复资产、冲突和身份漂移；
- 证据锚点准确性；
- EventRelation 准确性；
- 跨卷连续性；
- StandardStoryRecap 忠实度；
- Token、时间、失败率；
- 专家纠错时间；
- 用户是否能快速理解、定位和修正问题。

### 12.4 验证语料的角色

小型 fixtures 用来验证已冻结规则，例如：

- 普通动作不应建档；
- 传闻不应冒充真实事件；
- 联合原因不能拆成多个充分原因；
- 父子事件不能复制事实；
- Story segment 无独立情节时可以合法处置；
- Scope 投影不能变成第二事实源。

它们不能替代真实长篇实验，也不能证明产品已经达到作者、编辑和学者共同认可的质量。

## 十三、版本、证据与追加连载

### 13.1 EvidenceAnchor 绑定原文版本

证据锚点应绑定创建时的 `sourceTextEdition`。新版原文不能因为模糊搜到相似文字就静默继承旧确认。

- 文字和必要上下文未变、只发生位置移动时，可以经过可验证重定位；
- 支持文字或语境改变时，实际依赖它的命题进入复核；
- 支持文字删除时，锚点断链；
- 多个相似位置时保持歧义，不能自动任选。

### 13.2 追加连载与修订要分开

内容继续向后追加时：

- 已发布前缀的原文锚点可以在未变证明后继续有效；
- 新正文只扩展分析覆盖前沿；
- 新文本可以提高旧事件显著性、增加关系或推进 Plotline；
- 如果新证据推翻旧解释，只让真实依赖链复核；
- 当前版本可以完成分析覆盖，即使作品本身仍在连载、情节线未闭合。

修改、插入、删除或移动旧正文则属于 revision，需要按锚点和命题依赖局部处理，不能伪装成纯追加。

## 十四、这套教程能保证什么，不能保证什么

### 14.1 能提供的保证

在正确实现并通过生产验证后，这套方法有望提高：

- 事实与解释的可追溯性；
- 故事情节与叙述呈现的区分；
- 跨模块单写者一致性；
- 长篇事件、Plotline 与回顾的可修订性；
- 对不确定性和竞争解释的诚实表达；
- 技法提炼的来源透明度；
- 后续原创对原作方法的条件化复用。

### 14.2 不能由方法论文件单独保证

本文不能保证：

- AI 一定读懂整部长篇；
- 七模块同时运行时不会发生注意力分散；
- 所有文学解释都有唯一答案；
- 所有作者、编辑或学者都会接受同一分析；
- 真实读者一定产生预测效果；
- 生产成本必然可控；
- 当前 Prompt、Schema 或 UI 已经完成；
- 门禁越多，质量就越高。

质量来自“有限而正确的规则、程序化不变量、条件触发、真实长篇实验、专家纠错与用户可用性”的共同验证，而不是 Q 数量或文档长度。

### 14.3 当前剩余工作

- 其余六模块完成各自独有文学判断的深度审查；
- 共享 Evidence、命题、审查、版本与引用协议另行冻结；
- Block 17 比较生产实验臂并确定运行配置；
- Q30 的 fixtures、阈值、盲审与外部效度完成验证；
- Block 15 验证专题视角所需基础信息是否都有合格来源；
- Block 16 验证技法提炼不会把效果假说变成事实；
- 实际 UI 验证用户能快速阅读、定位来源和精确纠错。

## 十五、来源—结论映射与局限

| 来源类别 | 本文用它支持什么 | 不用它证明什么 |
| --- | --- | --- |
| Story/Discourse、叙述时间、聚焦理论 | 情节、叙述顺序、信息来源和聚焦必须区分 | 七模块是唯一文学分类 |
| 人物目标与情节研究 | 目标有助于理解行动和事件联系 | 每个事件都有明确人物目标 |

| 角色互动与关系弧研究 | 动态关系轨迹值得独立分析 | 关系模块的完整 Schema 已冻结 |
| Setting 与 storyworld 研究 | 环境、空间和氛围具有多种叙事功能 | 世界模块应拥有所有故事内事实 |
| Motif 与解释验证研究 | 反复模式和意义解释需要证据、替代解释与验证 | 存在唯一正确主题 |

当前资料较充分的领域是：

- Story/Discourse；
- 叙述时间与聚焦；
- 人物目标与情节关系；
- 文体学；
- 事件层级和事件关系；
- 长篇摘要评估。

- 关系动力的跨传统文学分析体系；
- 类型多样的世界设定分析；
- 主题、象征和意识形态解释的更多可操作教材；

- 真实读者接受数据；
- 七模块共同运行时的真实注意力、成本和质量表现。

## 结语

完整拆书不是给作品贴一组标签，而是建立一条能够回到原文、允许修正并服务后续创作的证据链：

```text
书、卷、章、Story segment 与原文范围
→ 七个核心分析模块
→ 有来源的跨模块解释
→ 专题视角与技法提炼
→ 去除原作专名的参考方法
→ 用户选择并治理的写作约束
```

七模块解决“谁拥有哪类事实和解释”，不是要求把一本书机械读七遍。Story segment 解决“在哪个稳定范围内分析”，不是作品唯一客观结构。门禁解决“已知错误怎样被拦截”，不是文学质量的自动保证。

WriteStorm V1 当前可以冻结的是故事情节领域语义及七模块顶层边界；仍需通过其余模块深审和真实长篇生产实验，证明这套方法在完整系统中既不遗漏关键内容，也不会因规则过载而降低分析质量。
